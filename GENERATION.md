# Media generation: what changed from Study 1 and Study 2

A running record of how the video overview, audio overview and infographic are
produced in this study, and how that differs from the two earlier studies. It is
kept up to date as the pipeline changes, for reporting. Newest entries are at the
bottom of the change log.

## Baselines

| | Study 1 (`reading-experiment-aom`) | Study 2 (`reading-experiment-mba`) | This study (`study-ug`) |
|---|---|---|---|
| Papers | One fixed paper per session set (e.g. Mroz et al. 2018) | Each participant uploaded their own paper | One fixed paper for everyone (Häfner, Stock & Oberst 2014) |
| How media were made | **Made in advance, not generated in the study.** Static files per paper (`audio.m4a`, `video.mp4`, `infographic.png`, plus Korean versions); the files carry Google encoder metadata, consistent with NotebookLM exports. No generation code in the repository | **Generated live for every participant** after upload, by Cloud Functions (below), ~5–6 min | Generated by the Study 2 pipeline, reworked (below). Default media made once and served to everyone; the customisation arms regenerate once per modality |
| Audio | Pre-made file | GPT-4o writes a two-host script → OpenAI `tts-1`, one call per line, concatenated | Same shape so far; see change log |
| Video | Pre-made `.mp4` | Narrated slideshow: Gemini 2.0 Flash plans ~30 scenes → `gemini-2.5-flash-image` draws each slide → OpenAI `tts-1-hd` narrates each scene. (A Veo 2 function existed but was not used by the interface) | Same shape so far; see change log |
| Infographic | Pre-made image | `gemini-3-pro-image-preview`, one call | Same so far |
| Paper text given to the models | — | First 30,000 / 25,000 / 15,000 characters (audio / video / infographic) of the uploaded PDF. Reason for the cut-off not recorded | Inherited; **found to hide the Results and Discussion from the video and infographic** — see Findings |
| Structure of each piece | — | Fixed arc (intro → background → method → results → implications) so that pieces made from different papers were comparable | Inherited; to become a default rather than a rule — see Decisions |
| Chatbot | `gpt-4o-mini` | `gpt-4o-mini` | `gpt-4o-mini` (under review) |

## Change log

**2026-09-24 — pipeline brought over from Study 2**
- The three generators moved into `functions/generation.js`, with no Firebase or
  HTTP inside, so the same code makes the default media and the customised runs.
- The paper ships as extracted text beside the functions instead of being
  uploaded on every call.
- Two models Study 2 named had been retired: `gemini-2.0-flash` → `gemini-3.6-flash`
  (video outline), `gemini-2.5-flash-image` → `gemini-3.1-flash-image` (slides).
- Very long outlines were cut off mid-JSON; the scenes that arrived whole are now
  kept instead of losing the run.
- Slide lettering is often misspelt by the image model ("SITRESS", "Burmout");
  `scripts/fix-scenes.js` redraws single slides.
- The video is served as one image and one narration file per scene with a
  manifest, instead of a single base64 blob.
- Video length estimates were corrected: narration runs ~5.7 s per scene, not
  the 9 s the outline plans for.
- The hand-made NotebookLM files used for early testing were replaced with
  pipeline output, so that all arms see content from the same generator.

**2026-09-24/25 — customisation**
- `generateCustom` Cloud Function: one regeneration per modality for the
  customisation arms, run as a job the page watches (progress, cancel, reload).
  A failed or cancelled run does not use up the participant's turn.
- The participant's request is added to the prompt as quoted data. It was first
  placed before the paper text and worded as optional; moved after the paper and
  worded as a requirement.
- Retries now cover dropped connections, not only HTTP 429/5xx.
- Speech calls run six at a time instead of one by one (podcast 44 s → 19 s).
- Every generated piece is stored with a `record.json`: the request, condition,
  models and the full script / narration / slide text, for later accuracy checks.

**2026-09-25 — customisation interface**
- Free text is for **content only** (what to focus on, how to explain it), with a
  warning that requests about voice, speed, colour or visual style may not be
  reflected.
- One setting per modality by button: length for video and audio; level of detail
  for the infographic.

## Findings (2026-09-26)

1. **The video and infographic never saw the results.** The inherited cut-offs
   give the infographic the first 15,000 and the video the first 25,000 of the
   paper's 51,017 characters; Results start at 26,018 and Discussion at 29,329.
   The audio (30,000) sees the results but loses most of the Discussion.
2. **The video narration contains claims the paper does not make**, where the
   audio, which saw the results, does not. Examples from the default video:
   - "up to seventy-five percent of university students experience moderate
     stress" — the paper cites *another* study of 212 *community college*
     students, 75% of whom reported *at least* moderate stress;
   - "perceived control over time increased significantly" — significant at four
     weeks only; a non-significant trend at two weeks;
   - "demands remained perfectly stable … no change in actual course difficulty"
     — perceived (self-reported) demands, with a non-significant change;
   - "anxiety and mental fatigue" — not measured; the measure is tension.
3. **No prompt tells the model to stay within the paper**, the input still
   contains the reference list (~25% of the text), page headers and tables
   flattened into prose, and sampling temperature is 0.7.
4. **Requests are under-applied, audio most of all.** The Study 2 prompts make
   the fixed arc mandatory and the request applies only "where it does not
   contradict the rules above", so a request to focus on one part loses to the
   rule to cover all of them; the ~1.5-minute podcast also spends several lines
   on greetings.
5. **Models are dated and mixed.** Chatbot `gpt-4o-mini`, audio script `gpt-4o`,
   speech `tts-1` date from 2023–24; audio comes from OpenAI and video and
   infographic from Google, which confounds modality with vendor.

## Decisions (2026-09-26)

- **Structure becomes a default, not a rule.** Study 2 fixed it for comparability
  across different papers; with one paper and customisation, a request decides
  the shape and the default arc only fills what the request leaves open.
- **Nothing is cut from the paper.** The whole text goes to every step, cleaned
  of references, page headers and flattened tables. No required-content list is
  imposed on outputs.
- **Target lengths of the default media: video 5 min, audio 2 min** (may be
  adjusted). The "default" setting offered to customising participants should
  land within about ±30 s of these; it need not match exactly.
- **Settings:** video and audio — length only (shorter / default / longer);
  infographic — level of detail (simpler / default / deeper).
- **Models are chosen by comparison**, not up front: once inputs and prompts are
  fixed, candidate model sets are run on the same paper and compared on accuracy
  against the paper, uptake of requests, and generation time.
- **The current default media are temporary** and will be regenerated with the
  final pipeline.
- **Generation time** is addressed last, after the model choice, since it
  depends on it.

## Planned order

1. Clean the paper text and pass it whole
2. Rework the prompts: grounding rule, lower temperature, request-first
   structure, relative length/detail settings, video scene count
3. Compare candidate model sets
4. Choose the models (including whether the chatbot changes)
5. Tune, then regenerate the default media
6. Generation time
